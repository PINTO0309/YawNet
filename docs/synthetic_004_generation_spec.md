# synthetic_004 追加生成指示書 — yaw 全周均衡化(下限 810 件/10° ビン)

- 版: v1.1(2026-09-01)全周対応(v1.0 の後方半球限定から拡張)
- 根拠データ: [data/yawpose/augmentation_plan.json](../data/yawpose/augmentation_plan.json)
  (`labels_fixed.jsonl` 23,651 件の 10° ビン集計、下限 = 前方側ビン中央値 810 件)
- 納品先: `data/synthetic_004/`(レイアウトは synthetic_002/003 に準拠)

## 1. 目的

yawpose データセットは正面帯(330°〜30°)に厚い一方、
(a) 後方半球 90°〜270° が手薄(特に真後ろ 175°〜190° は **0 件**)、
(b) 前方にも谷がある(20°〜70° と 300°〜330°)。
360° 全周で均質な yaw 回帰精度を得るため、**全 36 ビンの下限を 810 件**に揃える。

- 追加生成の必要数: **9,888 件**(後方 7,917 + 前方の谷 1,971)
- QA 落ち 15% を見込んだ生成指示数: **11,382 件**

## 2. yaw 規約(最重要 — 過去に符号事故が発生済み)

**本指示書の yaw はすべて yawpose 規約で記述する。**

- `yaw = 0°` : 正面(顔がカメラを向く)
- `yaw = +90°` : **画面左向きの完全プロファイル**(視聴者から見て左。被写体自身の右回転)
- `yaw = 180°` : 純粋な後頭部(顔は一切見えない)
- `yaw = 270°(= -90°)` : **画面右向きの完全プロファイル**
- 角度は 90°→180°→270° へ連続的に回転する(90°: 左横顔 → 135°: 左後方
  1/4(左耳と左頬の輪郭のみ)→ 180°: 真後ろ → 225°: 右後方 1/4 → 270°: 右横顔)

> **警告**: synthetic_002/003 の generation_plan は本規約と符号が逆
> (sixdrepnet360 検証で判明、約 3 割は生成モデル自体の左右取り違え)。
> 生成プロンプトには符号付き角度だけでなく、**「どちらの耳・頬が見えるか」を
> 必ず言語で明示**し、プロンプトと画像の左右一致を人手レビューで確認すること。
> 納品 jsonl の角度フィールド名は `yaw_yawpose` とし、規約の曖昧さを残さない。

## 4. 姿勢・構図の指定

- **pitch**: −10°〜+10° を基本(80%)、±10°〜±25° を 20%。極端ピッチは対象外
- **roll**: 視覚的にほぼ 0 を維持
- **カメラ仰俯角**: 0° を基本、±30° まで 30% 程度混在可(監視カメラ俯瞰を含む)
- 頭部の完全可視: 頭髪・頭頂・後頭部・顎(見える場合)・首・両肩の一部まで写す。
  頭部高さは画像高の 25%〜50%(目標 30%〜42%)、全周に頭部サイズの半分以上の
  余白、頭部の見切れ禁止(synthetic_002/003 と同じ構図要件)
- 帯別の見え方の言語アンカー(プロンプトに必ず含める):
  - 20–70 / 290–340(前方の谷): 顔の 3/4 ビュー。**両目が見えるが遠い側の目は
    輪郭に近い**。鼻筋が頬に重なり始める。向いている側の耳が見える
  - 90–110 / 250–270: 完全〜浅い後方プロファイル。**片耳と鼻先の輪郭**が見える。
    目は片目がぎりぎり見えるか見えない
  - 110–140 / 220–250: 後方 1/4。**耳と頬・顎の輪郭のみ**、目・鼻・口は見えない
  - 140–175 / 185–220: ほぼ後頭部。**耳が部分的に見える程度**、顔要素なし
  - 175–185: 純粋な後頭部。耳もほぼ見えない。**首筋と髪の流れ**で自然さを出す
- シナリオ例: 立ち去る人、掲示物を見る人、窓の外を見る人、レジ待ちの列、
  通話しながら歩く人、棚の商品を探す人、会話相手へ視線を向ける人(前方谷向け)等

## 5. 被写体・画質の多様性(synthetic_002/003 準拠)

- 架空の成人(18〜80 歳)。実在人物・著名人に似せない
- 性別・年齢・Fitzpatrick I〜VI・髪型(短髪/長髪/結髪/巻髪/薄毛/坊主等)・
  服装・帽子/フード/ヘッドホン等の頭部アクセサリ(後頭部の多様性に直結するため
  髪型バリエーションを特に厚く: 各ビンで髪型が偏らないこと)
- 背景: 実在感のある屋内外(オフィス/店舗/駅/路上/家庭)。単色背景禁止
- ライティング: 自然光/室内照明/夕方/低照度を混在
- カメラ: スマートフォン/監視カメラ相当の光学特性。イラスト調・CGI 調・
  美肌フィルタ・透かし・文字・枠・コラージュ禁止
- 画像サイズ: 1024x1536 または 1536x1024(JPEG)

## 6. 納品形式

```
data/synthetic_004/
  images/                    # <custom_id>.jpg
  generation_plan.jsonl      # 1 行 = 1 画像の生成意図
  image_sha256.jsonl
  auto_qa.jsonl              # 下記 QA 結果
  human_review.csv           # サンプリング人手レビュー結果(空テンプレ納品は不可)
  batch_state.json           # 生成ジョブの来歴
```

`generation_plan.jsonl` の必須フィールド:
`serial, bin(例 "yaw_180_190"), yaw_yawpose(整数度), pitch, cam, roll,
visible_side("left_ear"|"right_ear"|"none"|"profile_left"|"profile_right"|
"three_quarter_left"|"three_quarter_right"),
size, context, anchor, gender, age, skin_tone, hair, clothing, headwear,
lens_feel, background, lighting, custom_id, filename, prompt`

- `filename` は `yawp{+180}_pitch{+05}_cam{+00}_{serial:06d}.jpg` 形式
  (`yawp` = yawpose 規約であることを示す)

## 7. QA ゲート(自動)

synthetic_002/003 の auto QA を踏襲し、以下を全件実施する:

1. 画像整合: 存在・デコード可・サイズ一致・sha256 重複なし
2. DEIMv2(`models/deimv2_wholebody49_boxes_only.onnx`)で head(label 7)= 1 件、
   head 高さ比 25%〜50%、全側余白 ≥ 頭部の半分
3. **向きの整合チェック(帯別)**:
   - **前方の谷(20°〜80°、280°〜340°)**: sixdrepnet360 + hrffa ランドマーク
     (`scripts/verify_labels_sixd.py` / `scripts/study_landmark_yaw.py` の方式)で
     **符号と概算角度を全件自動検証**。符号不一致は不合格
   - `90° ≤ |signed| ≤ 95°`: 同上の方式で符号一致を確認
   - `|signed| > 95°`(後方帯): **Face(label 16)score ≥ 0.5 が検出されたら
     不合格候補**(顔が見えている = 意図した後方向きでない)
4. 身体の解剖学的整合(途切れ・溶け込み・浮遊の禁止)は synthetic_003 の
   基準に準拠

## 8. 人手レビュー(必須)

- **後方帯(|yaw|>95°)**: 自動符号検証が不可能なため、**各ビン最低 10% を
  無作為抽出して人手レビュー**する。判定項目: photorealism / intent_match
  (特に**左右の耳・頬の見え方がプロンプトと一致するか**)/ framing /
  body_integrity
- **前方の谷**: 自動検証が効くため抽出率 5% でよい(photorealism / framing 中心)
- intent_match 不合格率がビンで 15% を超えた場合、そのビンは全数レビューに
  切り替える(synthetic_002 の「空テンプレート納品」を繰り返さないこと)
